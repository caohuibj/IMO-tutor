# Solution Compare

Use when a reference/official solution is supplied after the student's Attempt has ended.

## Steps

1. Verify the reference solution independently; do not assume it is superior merely because it is official.
2. Compare the two approaches on:
   - core insight;
   - proof length/technical load;
   - rigor risk;
   - natural discoverability in contest conditions;
   - prerequisite sophistication;
   - generalizability;
   - clarity of exposition.
3. Identify ideas unique to the student's solution that are worth preserving.
4. Identify ideas from the reference solution that should be added to the learning note.
5. Update method/concept tags only when the new solution reveals genuinely new classifications.

Do not overwrite the student's original review. Append the comparison inside the relevant `attempt_id` block in the durable note. Preserve provenance: reference-derived ideas are `REFERENCE`, never silently reattributed to the student.

## Post-comparison refresh

If and only if the relevant Attempt originally completed through explicit `此题完成`, a reference solution that reveals genuinely new mathematics may selectively refresh:

- Module 3 — Mathematical Extraction;
- Module 4 — Higher Mathematics Bridge;
- Module 5 — Reinforcement Problems;
- Module 6 — Visual Model.

Keep the original student-derived entries and add/reference the new material with `REFERENCE` provenance. Do not rerun Historical Transfer solely because an official solution was supplied unless the user explicitly asks for a new longitudinal comparison.

If the Attempt ended by give-up/H6 without `此题完成`, preserve the completion gate: perform the requested solution comparison, but do not automatically backfill the six-module post-review extension.
